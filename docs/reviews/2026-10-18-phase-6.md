## Findings

### CR6-01 · Minor · Changing the novel language, or Randomize, replaces the rank ladder under existing characters

- **Where:** `src/pages/SettingTab.tsx` (`change` → `switchSetLanguage`, `randomize` → `applySet`), `src/lib/curatedSets.ts`
- **Contract:** spec 8 (curated sets: swap untouched text; Randomize between chapters), spec 7.3 (rank is a choice from the setting's ladder), decision 85
- **Problem:** In a story that already has characters, switching the novel language swaps an untouched ladder to the new language ("煉氣, 初期" instead of "Qi Refining, Early"), and Randomize swaps it for another set's ladder. The characters keep their old ranks. Once the setting is saved, every character form shows its rank as "(not in the rank ladder)" and refuses to save until a rank is picked again. The prompt then sends a ladder and character ranks that do not match, and End Chapter drops rank proposals that use the old names. The spec allows both actions between chapters but says nothing about the ranks.
- **Breaks when:** A cultivation story with a main character on "Qi Refining, Early" switches its language to 繁體中文 on the Setting page and saves. Proven by test N in `test-results/review-6/review.test.ts`.
- **Suggested fix:** Pick one in the spec, then code it. (a) Leave the ladder out of the language swap and Randomize once any character has a rank. (b) Map each character's rank to the same position in the new ladder when the setting is saved, with a note to the user. (c) Warn before saving that N characters' ranks no longer match. (a) is the smallest change.
- **Test to add:** U-CS or U-SG: a language switch (and Randomize) on a story whose main character has a rank keeps every character's rank valid (spec 8).
- **Status:** Fixed 2026-10-18 by a wider rule, decided with the user (decision 89): the novel's language is fixed once the story has started (first block of chapter 1), and Randomize is only offered before that. Characters are created before chapter 1 too, but nothing has been written with their ranks yet, and the user can re-pick them. `hasStarted` and a guard in `saveSetting` (U-SG), the read-only field and hidden Randomize on the Setting page (E2E-44).

### CR6-02 · Minor · The End Chapter prompt gives an English rank example in a Chinese story

- **Where:** `src/lib/endChapter.ts`, `describeField`, `rank` case
- **Contract:** spec 6.5 (choice values in the novel's language), decision 84
- **Problem:** The field list says `cultivation_rank: one of the ranks in the setting's rank ladder, e.g. "Qi Refining, Early"`, whatever the language. In a Chinese story the ladder is Chinese, so the example nudges the model to answer in English, and `checkProposals` then drops the proposal as "not in the ladder". Ranks are not choices, so the mapping back of decision 84 does not cover them.
- **Breaks when:** A 繁體中文 cultivation story ends a chapter in which the main character breaks through. Proven by test YY.
- **Suggested fix:** Take the example from the story's own ladder (its second rank option), or list the rank options outright; the ladder is short.
- **Test to add:** U-EC: a Chinese story's End Chapter prompt names a rank from its own ladder, not "Qi Refining, Early".
- **Status:** Fixed 2026-10-18. The field line lists every rank of the story's ladder (`ranks` in `buildEndChapterPrompt`); U-EC test.

### CR6-03 · Minor · Random name in the review's "Edit first" form can give a name a character already has

- **Where:** `src/pages/ChapterReview.tsx` (opens `CharacterForm` without `others`), `src/pages/CharactersTab.tsx` (`pickName`)
- **Contract:** spec 7.1 ("a name … that no character of the story has"), spec 5.4 / decision 78 (a new character whose name exists is refused)
- **Problem:** `CharacterForm` skips names from `others`, which defaults to `[]`. The Characters tab passes the story's characters, but the review's "Edit first" form passes none, so Random name may pick an existing character's name. Saving there goes through `saveCharacter`, which does not check names, so the story can end up with two characters of the same name. The button also replaces the name the AI gave, which is rarely what "Edit first" is for.
- **Breaks when:** In the review, "Edit first" on Elder Wu, Random name gives the name of a character already in the story, then Save.
- **Suggested fix:** Pass the story's characters as `others` from the review too (it can load them with `listCharacters`), or hide Random name in that form.
- **Test to add:** E2E or a page-free unit test of the name-pool call with the story's characters (spec 7.1).
- **Status:** Fixed 2026-10-18. The review loads the story's characters and passes them as `others`. The name-pool rule itself is covered by U-CS; the page wiring has no test of its own.

### CR6-04 · Minor · An existing v0.1 user's UI switches to the system language after the update

- **Where:** `src/lib/settings.ts`, `loadSettings`
- **Contract:** spec 11 ("On first launch it starts from the system's language")
- **Problem:** A settings file without `uiLanguage` (every v0.1 install) gets the detected language. On a Chinese Windows, a user who has used the English UI until now sees it in Chinese after updating. That may be welcome, but it is not what spec 11 says.
- **Breaks when:** Updating from v0.1 on a system set to zh-TW or zh-CN.
- **Suggested fix:** Decide in the spec. Either say "until a language is chosen" (the code's behaviour, and the comment in `loadSettings` already says so), or default an existing file without the key to English.
- **Test to add:** U-SE for whichever rule is chosen.
- **Status:** Won't fix, decided with the user 2026-10-18: no one outside the author has a v0.1 install, so testers start on the new rule. Spec 11 now says "until a language is chosen", which is what the code does; U-SE already covers it.

### CR6-05 · Nit · After the stream_options retry, the AI log records the first request body

- **Where:** `src/lib/novel.ts` `loggedCall` (`chatBody(model, messages)`), `src/lib/ai.ts` retry
- **Contract:** spec 3 (the AI call log records the messages "exactly as sent"), decision 87
- **Problem:** When a provider rejects `stream_options`, the request that succeeds has no `stream_options`, but the log still shows it. The messages are right; only a body field differs. Development builds only.
- **Suggested fix:** Let `streamChat` report whether it retried (or the body it sent), and log that.
- **Status:** Fixed 2026-10-18. `streamChat` reports each body it sends (`onRequest`), and `loggedCall` logs the last one; U-NV test.

### CR6-06 · Nit · The progress dialog does not take focus

- **Where:** `src/components/ProgressDialog.tsx`
- **Contract:** decision 88 (a dialog that keeps the user from clicking around)
- **Problem:** The dialog is `aria-modal`, but focus stays on the End Chapter button behind it, so a keyboard user can tab to controls under the overlay. `Modal.tsx` has the same gap, so this is app-wide, not new. The summary branch of the leave guard in `StoryWorkspace.tsx` is now reachable only by closing the app, since the overlay covers the rail; that is fine, and spec 9 says so.
- **Suggested fix:** Focus the dialog (or its Stop button) on open, and keep Tab inside it.
- **Status:** Fixed 2026-10-18 for every dialog: `useDialogFocus` (in `Modal` and `ProgressDialog`) moves focus in unless a field took it, keeps Tab and Shift+Tab inside, and gives focus back on close; E2E-45.

### CR6-07 · Nit · In `npm run dev`, a hot reload of a translation file resets the language to English

- **Where:** `src/i18n/index.ts` (`let current = "en"`), `src/App.tsx`
- **Problem:** Vite reloads the module with its default, while App keeps its state and does not call `setLocale` again. Development only; a page reload fixes it. It confused the visual check during the build.
- **Suggested fix:** Call `setLocale(settings.uiLanguage)` in an effect in `App` keyed on the setting, or keep the locale on `globalThis`.
- **Status:** Fixed 2026-10-18. The locale is also kept on `globalThis`, so a re-run module starts with it; U-IN test.

### CR6-08 · Nit · A hand-edited draft whose actions contain a non-string shifts the notes

- **Where:** `src/lib/draft.ts`, `normalizeDraft`
- **Problem:** Non-string actions are filtered out first, then notes are matched by the new index, so after a dropped action each note sits under the wrong action. Only a hand-edited file can cause it.
- **Suggested fix:** Filter actions and notes together, by pair.
- **Status:** Fixed 2026-10-18; U-DR test.
