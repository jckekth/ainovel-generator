# Security review: all

**Date:** 2026-11-01 · **Reviewer:** security-expert agent · **Scope:** the whole repository: Tauri shell (`src-tauri/`), React UI (`src/`), AI boundary (`src/lib/ai.ts`, `pictures.ts`), storage and parsing (`storage.ts`, `markdoc.ts`, `stories.ts`, `endChapter.ts`), secrets (`secrets.ts`, `lib.rs`), dependencies, dev tooling (`scripts/`, Vite, Playwright, `.claude/`), build output (`dist/`).
**Tools run:** `npm audit --omit=dev`: 0 vulnerabilities. `npm audit`: 2 high (vite 7.3.6, undici 7.30.0 via jsdom), both dev only. `cargo audit`: not installed (`cargo` has no `audit` subcommand), not run. Grep of the tree (outside `node_modules`, `target`, `dist`, `coverage`) for API keys and tokens: none found besides the mock's `sk-test-*` keys. `dist/` checked for source maps: none.

## Summary

Overall risk is low to moderate. The app has no HTML sink: AI output, story files and provider errors are all rendered as React text, the API key stays in the OS credential store and is never logged, YAML is parsed safely, and the HTTP plugin strips the key on cross-host redirects. The biggest risk is structural: the webview has no Content Security Policy, and its capabilities let any script inside it read the key, send it anywhere, write files into the data folder and then open (run) them. Today nothing injects script, so this is a missing safety net rather than an open hole, but one rendering mistake in future (a markdown renderer, a link in AI output) would become key theft and code execution. The dev server's Vite version has a known high advisory that matters on this Windows dev machine. `cargo audit` could not be run and the Tauri-only paths were read, not exercised.

## Threat model

- **Assets:** the text and image API keys (OS credential store; sessionStorage in the browser preview); story content and pictures under the app data folder; the user's machine (the webview can reach Tauri IPC).
- **Entry points:**
  - AI responses: streamed chat text, End Chapter JSON, image responses (base64 or a `url`), error bodies. Reachable by the configured provider, or by anyone who controls or intercepts it (plain `http` base URLs).
  - Story files on disk (`story.json`, `*.md` with YAML headers, `draft.json`, `pictures.json`): hand-edited by the user; writable by any process running as the user.
  - Settings form (base URLs, keys, model names): the user.
  - Tauri commands (`get_api_key` and friends) and plugin IPC (fs, http, opener): any script running in the webview.
  - Dev servers: Vite on `localhost:1420` and the mock AI on `127.0.0.1:8787`, reachable by local processes and, through the browser, by any web page the developer visits while they run.
- **Attackers:** a hostile or compromised AI provider or proxy; a network attacker on plain-`http` endpoints; a malicious web page visited while dev servers run; a compromised npm or crates package. A local process running as the same user is out of scope for most findings (it can already read the credential store).

## Findings

### SEC-01 · Medium · No Content Security Policy in the app webview

- **Where:** `src-tauri/tauri.conf.json:23` (`"csp": null`)
- **Category:** config
- **Attacker and impact:** anyone who gets HTML or script into the webview (today: no known path; in future: a markdown renderer, a `dangerouslySetInnerHTML`, a compromised npm package in the bundle). With no CSP, injected or inline script runs, loads remote script, and has full Tauri IPC: `invoke("get_api_key")` / `get_image_key` returns both keys in plain text, and the HTTP plugin (scope `https://**`, `http://**`, `default.json:13-18`) sends them to any host without CORS limits. Combined with SEC-02 it is code execution on the user's machine.
- **How:** the app renders a lot of attacker-influenced text (every AI answer, provider error messages, hand-edited story files). None of it reaches an HTML sink today (grep for `dangerouslySetInnerHTML`, `innerHTML`, `eval`, `new Function`, `href=`: no hits in `src/`), so this is a missing second line of defence. The wide HTTP scope itself is needed by design (decision 2: any base URL), which makes CSP the only place to contain injected script.
- **Fix:** set a strict CSP, for example `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' blob: data:; media-src 'self' blob:; font-src 'self'; connect-src ipc: http://ipc.localhost`. AI calls go through the HTTP plugin (Rust), so `connect-src` does not need provider hosts. Check that Vite's dev build still works (`devCsp` or a looser dev policy). Needs a decision row.
- **Verify:** in the built app, DevTools console `fetch("https://example.com")` and an injected `<script>` element are both blocked by CSP; all E2E and the real-app checklist still pass.

### SEC-02 · Medium · Opener scope lets the webview run any file it writes into the data folder

- **Where:** `src-tauri/capabilities/default.json:22-23` (`opener:allow-open-path` with `$APPDATA/**`), with `default.json:10` (`fs:allow-appdata-write-recursive`)
- **Category:** permissions
- **Attacker and impact:** any script running in the webview (see SEC-01). It can `writeFile("x.bat" | "x.hta" | "x.lnk", …, { baseDir: AppData })` and then `openPath("<appdata>/x.bat")`. The opener plugin opens the path with the system's default handler (ShellExecute on Windows), and I found no executable filter in `tauri-plugin-opener` 2.7.0, so the file runs as the user. This turns script injection into arbitrary code execution.
- **How:** the only caller is Settings, "Open data folder", which opens the folder itself (`src/pages/Settings.tsx:104`, `src/lib/platform.ts:36-40`). Nothing needs `$APPDATA/**`.
- **Fix:** allow only `{ "path": "$APPDATA" }`, or use `revealItemInDir` (already allowed by `opener:default`) on the data folder instead of `openPath`.
- **Verify:** in the built app, `openPath(await appDataDir() + "/stories")` fails with a scope error while "Open data folder" still works.

### SEC-03 · Medium · Vite dev server version with high advisories, on a Windows dev machine

- **Where:** `package.json:33` (`"vite": "^7.0.0"`, installed 7.3.6; `npm ls vite`)
- **Category:** dependency
- **Attacker and impact:** a web page the developer opens while `npm run dev` or `npm run tauri dev` runs. Vite 7.3.6 bundles `launch-editor` and mounts `/__open-in-editor` (`node_modules/vite/dist/node/chunks/config.js:25690`). Advisories GHSA-698v-4r3x-3vcv (Windows `%` not escaped) and GHSA-r825-w8mm-5pxw (editor flag injection) can lead to command execution on the developer's machine through a cross-site GET to `http://localhost:1420/__open-in-editor?file=…`. GHSA-9jrq-w75r-8gcw (cross-origin script execution) is also listed. Not in the shipped app: `npm audit --omit=dev` is clean.
- **How:** Unconfirmed: exploitation depends on the configured editor (VS Code is installed here). Confirm by reading the advisories against Vite 7.3.6's middleware; do not test against anything outside this machine.
- **Fix:** update Vite to a patched 7.x (`npm audit` says a fix is available) and rerun `npm run test:all`.
- **Verify:** `npm audit` shows no vite entry.

### SEC-04 · Low · The image response's `url` is fetched with no host, scheme or size check

- **Where:** `src/lib/ai.ts:313-320`
- **Category:** AI boundary
- **Attacker and impact:** a hostile or compromised image provider. It answers `/images/generations` with `{"data":[{"url":"http://192.168.1.1/…"}]}` and the app, through the Rust HTTP plugin (scope allows any `http`/`https` URL, no CORS), makes a GET from the user's machine to any address, including `localhost` and the LAN. The key is not sent with it, and the response is only saved as a picture, so the attacker cannot read the result: this is a blind request from the user's network, plus an unbounded download into the data folder (`arrayBuffer()` with no limit, `pictures.ts:170`).
- **How:** set the image base URL to a server that returns such a `url`; watch the request leave the machine.
- **Fix:** accept only `https:` URLs (or the image base URL's own origin), refuse private and loopback addresses unless the base URL itself is local, and cap the size (for example 20 MB) for both `url` and `b64_json`.
- **Verify:** a unit test in `ai.test.ts` where a `url` of `http://127.0.0.1/…` or `file:` gives `BAD_FORMAT` without a second fetch.

### SEC-05 · Low · The key is sent over plain `http` to any host without a warning

- **Where:** `src/lib/ai.ts:53-58` (`checkConfig` accepts `http://` for any host); `src/i18n/en.ts:346` (hint says nothing about it)
- **Category:** secrets
- **Attacker and impact:** a network attacker (public Wi-Fi, a proxy) when the user enters an `http://` base URL for a remote provider, by mistake or from a tutorial. The `Authorization: Bearer <key>` header and the whole story go in clear text. The same applies to a same-host `https`→`http` redirect: the HTTP plugin keeps the key when only the scheme changes (`reqwest` 0.12 `remove_sensitive_headers` checks host and port only). Plain `http` to `localhost` is a legitimate choice for local models.
- **How:** set the base URL to `http://api.example.com/v1`, Test connection: the key travels unencrypted.
- **Fix:** allow `http://` only for `localhost`, `127.0.0.1`, `[::1]` and private ranges, or show a plain-words warning before saving a non-local `http` URL. Spec 9 and a decision row.
- **Verify:** unit test: `checkConfig` with `http://api.example.com` throws or returns a warning; `http://localhost:11434/v1` passes.

### SEC-06 · Info · `story.json`'s `id` field is trusted for folder paths

- **Where:** `src/lib/stories.ts:75` (the id comes from the file), `stories.ts:112-114` (`deleteStory` removes `stories/<id>`)
- **Category:** file handling
- **Attacker and impact:** only someone who can already write to the data folder (the user hand-editing, or a local process). A `story.json` with `"id": ""` makes Delete remove `stories/` (every story); an id naming another story deletes that one. `../` is blocked by Tauri (`SafePathBuf` refuses parent components), so it cannot leave the data folder. No security boundary is crossed today; it becomes one if story import or sharing (Later list) is built.
- **Fix:** use the folder name from `store.list` as the id (ignore or check the field), and refuse ids that do not match `^[a-z0-9-]+$`.
- **Verify:** unit test: a story folder whose `story.json` says `"id": ""` lists under its folder name and deletes only itself.

### SEC-07 · Info · Mock AI server prints full keys and serves the last prompt to any origin

- **Where:** `scripts/mock-ai-server.mjs:418` (`console.log(... key=${fullKey})`), `:87` (`Access-Control-Allow-Origin: *`), `:422-430` (`/v1/_last-request`)
- **Category:** dev tooling
- **Attacker and impact:** a web page open while `npm run mock-ai` runs can read the last request (story prompt) for a known test key; a real key pointed at the mock by mistake is printed to the terminal. It binds to `127.0.0.1` (good) and only sees test stories, so the impact is small.
- **Fix:** print only a key prefix; optionally restrict CORS to `http://localhost:1420`.
- **Verify:** run the mock, call it with `sk-realkey…`: the log shows `sk-rea…` only.

### SEC-08 · Info · Dev-only packages with install scripts and advisories

- **Where:** `package-lock.json:2289` (`ffmpeg-static`, `hasInstallScript`: its postinstall downloads an ffmpeg binary from GitHub), `jsdom` → `undici` 7.30.0 (8 advisories, high, `npm audit`)
- **Category:** dependency
- **Attacker and impact:** supply chain on the developer machine. `undici` is used only inside Vitest's jsdom, which talks to no network in these tests, so the advisories have no reachable path. `ffmpeg-static` runs a download at `npm install` time and is only needed by `npm run encode-music`.
- **Fix:** `npm audit fix` for undici (via jsdom); consider making ffmpeg a documented manual install, or keep it and accept the postinstall.
- **Verify:** `npm audit` clean for undici.

### SEC-09 · Info · No size limits on AI responses

- **Where:** `src/lib/ai.ts:182-185` (SSE buffer grows until a newline), `ai.ts:405` (text grows without limit), `ai.ts:105` (error body read in full before the 300-character cut), `ai.ts:311` (`b64_json` decoded in full)
- **Category:** AI boundary
- **Attacker and impact:** a hostile provider can make the app use unbounded memory (a stream with no newline, a huge error page or image) until the webview crashes. Denial of service only; the user can change provider.
- **Fix:** cap the buffer and total response (for example a few MB for chat, 20 MB for images) and fail with `BAD_FORMAT`.
- **Verify:** unit test that a 10 MB line with no newline ends in an `AiError`, not a hang.

## Good practices found

- **Key storage:** keys live only in the OS credential store (`src-tauri/src/lib.rs`, decision 3); `app-settings.json` holds no key (`settings.ts:1`); the browser preview uses sessionStorage, not localStorage (`secrets.ts`). The key field is `type="password"` with `autoComplete="off"` and is cleared after saving (`Settings.tsx:58-68,155`).
- **No key in logs:** the dev AI log records the body and base URL only, never headers (`devlog.ts`, decision 46), and is off in release (`import.meta.env.DEV`). No `console.log` of keys in `src/`.
- **No HTML sinks:** all AI and file text is rendered as React text; `tRich` builds nodes, not HTML (`src/i18n/rich.tsx`). External links come only from constants (`SetupGuide.tsx` `PROVIDERS`, `about.config.ts`).
- **Redirects:** the Tauri HTTP plugin uses a scope-aware redirect policy, and reqwest drops `Authorization` on any cross-host redirect, so the key does not follow a redirect to another host.
- **Parsing:** `yaml` 2.9.1 defines `__proto__` keys as own properties (no prototype pollution) and caps alias expansion (`maxAliasCount` 100). End Chapter proposals are checked against known characters, field keys, options and validation before the user can approve them (`endChapter.ts:294-360`); prompt injection can change story text, not take actions.
- **Paths:** ids are slugs (`makeId`); picture names are digits only (`versionKey`); `pictures.json` entries with `..` are skipped (`pictures.ts:274`); Tauri's fs plugin refuses `../` anyway.
- **Capabilities:** fs is limited to the app data folder; no shell plugin; `withGlobalTauri` is off; Rust `tauri` has no `devtools` feature, so release builds have no devtools; no source maps in `dist/`; no updater configured.
- **Dev servers:** the mock AI binds to `127.0.0.1`; Vite binds to localhost (default) with a fixed port.
- **Dependencies:** `npm audit --omit=dev` is clean; `package-lock.json` and `Cargo.lock` are present; the project itself has no lifecycle scripts.
